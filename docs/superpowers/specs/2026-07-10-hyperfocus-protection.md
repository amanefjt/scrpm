# scrpm 過集中保護・負荷可視化 仕様

## 背景・目的

ユーザー（ADHD 診断あり）には以下の問題がある:

1. 過集中時、休憩オーバーレイで「作業をやめる」を押した後、タイマーの再開を忘れて
   計測なし・休憩なしで作業し続けてしまう（以後の 25 分介入が一切なくなる）
2. 休憩が普通に終わっても Idle に戻るだけなので、再開を忘れる穴が平常時にもある
3. 作業ログを付けられず「最近働きすぎ」に気づけないまま体調を崩す

設計原則（成人 ADHD 研究の推奨に基づく）:
- **デフォルトが常に計測中**: タイマーが止まった状態を例外にする。離脱は明示的な選択、
  継続は自動
- 内的手がかり（疲労の自覚・再開の意思）に依存する仕組みを排除し、外部トリガーを自動化する
- 負荷の可視化は主観に頼らず自動記録から行う

## 機能一覧

### F1. 延長回数の上限

> **2026-08-09 削除済み**: 延長カウントが休憩を跨ぐたびにリセットされ、延長を繰り返せば
> 休憩を無限に先延ばしできる仕様だったため、過集中保護の意図に反するとして「作業を延長する」
> ボタン自体を撤廃した。詳細: `docs/superpowers/specs/2026-06-09-extend-work-timer-design.md`。
> 以下は当時の仕様の記録。

- 休憩オーバーレイの「作業を延長する」は **1 セッションチェーンにつき最大 2 回**まで
- 上限到達後はボタンを非表示（現状の 60 秒経過時と同じ扱い。「作業を再開する」は従来通り）
- 延長カウントは `TimerStateManager` が保持し、セッション記録が確定するタイミング
  （`stopWork()` / `resumeWork()` / `finishBreak()`）でリセット
- 定数: `Durations.swift` に `maxExtensions = 2`

### F2. 休憩終了後の自動再開

- 現状: `finishBreak()` で `phase = .idle`（`TimerStateManager.swift:98`）
- 変更後: `finishBreak()` はセッション記録を従来通り行った上で、**自動的に次の
  Working セッションを開始する**（`phase = .working`、新しい `workStartedAt`）
- 告知は**無音**。オーバーレイが閉じてメインウィンドウがカウントダウン表示に戻るだけ
- タイマーを止めたい場合は従来通り「作業をやめる」（休憩中オーバーレイ / Working 中の
  メイン UI）を使う

### F3. Idle 中の作業検出 → 無音自動開始

- 対象: `phase == .idle` のとき（＝ユーザーが明示的に「作業をやめる」を選んだ後）
- PC への入力が継続していることを検出したら、自動で `startWork()` を呼ぶ
- 検出方法: `CGEventSource.secondsSinceLastEventType(.combinedSessionState, eventType:)`
  でグローバルな最終入力からの経過秒を取得（sandbox 無効なので追加権限不要。
  keyDown と mouseMoved 等、複数イベント種の最小値を取る）
- 判定ヒューリスティック: Idle 中 30 秒間隔でポーリングし、「直近 30 秒以内に入力あり」が
  **連続 10 回**（= 約 5 分間の継続的な活動）に達したら自動開始。入力が途切れたら
  カウントをリセット
- 告知は**無音・オーバーレイなし**。メインウィンドウが Working 表示に切り替わるのみ
- 誤検出（PC で動画を見ている等）は許容する。止めるのはワンクリックであり、
  止め忘れによる害の方が大きいという設計判断
- 定数: `idlePollingInterval = 30`、`idleActivationCount = 10`
- ポーリングは `phase == .idle` の間のみ動かす（working/breaking 中は停止）

### F4. 「作業をやめる」ボタンの遅延有効化（休憩オーバーレイのみ）

> **2026-08-09 変更済み**: 「やめる」だけが先に有効化されると、本当は作業を続けたい
> 場合でも早計に「やめる」を押してしまう非対称があったため、`stopButtonDelay`（10秒）は
> 廃止し「作業を再開する」と同じ `breakActionDelay`（3分）で両ボタンを同時表示する方式に
> 統一した。以下は当時の仕様の記録。

- 休憩オーバーレイ表示から **10 秒間**は「作業をやめる」を無効化
- 表示: グレーアウト＋残り秒数のカウントダウン（「あと何秒で押せるか」を見せて
  苛立ちを防ぐ）。10 秒経過後に通常の有効状態へ
- **簡単に外せること**: `Durations.swift` の `stopButtonDelay: TimeInterval = 10` を
  `0` にすれば即時有効（実質オフ）になる実装にする。分岐を UI に散らさない
- Working 中のメイン UI の「作業をやめる」には適用しない（対象は休憩オーバーレイのみ）

### F5. Working 中の無操作検出 → 無音自動中断

- 対象: `phase == .working` のとき
- F3（Idle → Working）と対称の仕組み。PC への入力が途絶えていることを検出したら、
  自動で `stopWork()` を呼び中断セッションとして記録し Idle に戻す
- 検出方法・ポーリング間隔は F3 と共通（`secondsSinceLastUserInput()`,
  `idlePollingInterval` 間隔でのポーリング）。判定は不等号の向きが逆になるだけ
- 判定ヒューリスティック: Working 中 `idlePollingInterval` 秒間隔でポーリングし、
  「直近 `idlePollingInterval` 秒以内に入力なし」が連続 `workInactivityDeactivationCount`
  回（= 約 5 分間の無操作）に達したら自動中断。入力があればカウントをリセット
- 開始判定・終了判定ともに同じ約5分としている（開始側を早める、終了側を長めにする
  といった非対称運用も検討したが、まずはシンプルに揃えて様子を見る判断）
- 60 秒以上作業していれば `stopWork()` 内の既存ロジックにより中断セッション
  （`completed: false`）として記録される
- Breaking 中は対象外（休憩中は元々作業していない前提）。`finishWork()` で
  監視を停止し、`resumeWork()` で Working に戻るタイミングで再開する
- 告知は F3 と同様に**無音**。中断してもオーバーレイ等は出さず、メインウィンドウが
  Idle 表示に切り替わるのみ
- 定数: `workInactivityDeactivationCount = 10`（`idlePollingInterval` 30秒 × 10 = 5分）
- Idle 監視（F3）と Working 監視（F5）は `TimerStateManager` の単一の仕組み
  （`startActivityMonitor()` / `stopActivityMonitor()` / `checkActivity()`）に
  統合されている（旧 `startIdleMonitor` 等から改名）

### F6. 週次負荷の可視化と休養警告

既存の WorkSession 記録（SwiftData）を集計して使う。手入力は一切追加しない。

**F6a. 表示（先行実装）**
- 履歴画面（週タブ）に「今週の合計: X時間」「過去4週平均: Y時間」を併記
- まずは数字の感覚を掴むためのデータ収集期間として、表示のみから始める

**F6b. 休養日ゼロ警告（本命・F6a と同時に実装）**
- 「休養日」の定義: その日の記録合計が `restDayThreshold = 1800`（30分）未満の日
- **直近 `noRestWarningDays = 10` 日間に休養日が 1 日もない**場合、履歴画面と
  メイン画面（Idle 時）に警告バナーを表示:
  「10日間休みなく作業しています。休養日を取ることを検討してください」
- 「軽く体を壊すまで追い込む」パターンの直接指標は総時間より無休の連続日数、
  という判断に基づく

**F6c. 週平均比警告（後日、閾値はデータを見て決める）**
- 直近 7 日間の合計が過去 4 週間の週平均の 130% を超えたら警告
- 数週間分のデータが貯まり、F6a の数字の感覚が掴めてから有効化する
- 実装するなら `weeklyOverloadRatio = 1.3` を定数化し、比較対象データが
  4 週間分未満の間は警告を出さない

## 状態遷移（変更後）

```
[Idle] ──「作業開始」──────────────→ [Working]
[Idle] ──約5分の入力継続を検出────→ [Working]（F3、無音）
[Working] ──25分経過──→ [Break]
[Working] ──「作業をやめる」──→ [Idle]
[Working] ──約5分の無操作を検出────→ [Idle]（F5、無音自動中断・中断セッション記録）
[Break] ──5分経過──→ [Working]（F2、無音自動再開。従来は Idle）
[Break] ──「作業を延長する」（最初の60秒のみ・最大2回）──→ [Working(2分)]  ※2026-08-09 削除済み（F1参照）
[Break] ──「作業を再開する」（60秒経過後）──→ [Working]  ※2026-08-09 breakActionDelay(3分)に変更（F4参照）
[Break] ──「作業をやめる」（表示から10秒後に有効化）──→ [Idle]  ※2026-08-09 breakActionDelay(3分)に変更（F4参照）
```

## 定数まとめ（Durations.swift に追加）

| 定数 | 値 | 意味 |
|------|-----|------|
| `maxExtensions` | 2 | 延長の上限回数（2026-08-09 削除済み。F1参照） |
| `stopButtonDelay` | 10 | 「作業をやめる」有効化までの秒数（0 で無効）（2026-08-09 `breakActionDelay` に統合され削除。F4参照） |
| `idlePollingInterval` | 30 | Idle 中の入力ポーリング間隔（秒） |
| `idleActivationCount` | 10 | 自動開始までの連続検出回数（30秒×10 = 約5分） |
| `workInactivityDeactivationCount` | 10 | 自動中断までの連続無操作検出回数（30秒×10 = 約5分） |
| `restDayThreshold` | 1800 | この秒数未満の日を「休養日」とみなす |
| `noRestWarningDays` | 10 | 休養日ゼロ警告の対象期間（日） |

## テスト用短縮値

既存のテスト手順（`workDuration = 70` 等）に加え:
- `idlePollingInterval = 5`、`idleActivationCount = 3`（約15秒で自動開始）
- `workInactivityDeactivationCount = 3`（`idlePollingInterval = 5` なら約15秒で自動中断）
- `stopButtonDelay = 3`
- `noRestWarningDays` はテスト困難なので、判定ロジックを日付を引数に取る純関数に
  切り出してユニットテスト可能にする（SwiftData のクエリと分離する）

テスト後は必ず本番値に戻すこと。

## 実装上の注意（既存コードとの整合）

- セッション記録の仕組み（`workAccumulatedDuration` の累積、記録タイミング）は
  変更しない。F2 で `finishBreak()` が Working を開始しても、記録確定 →
  新セッション開始の順序を守る
- F2/F3 の自動開始は `startWork()` を経由し、状態初期化のパスを一本化する
- オーバーレイの show/hide は従来通り `ScrpmApp` の `.onChange(of: phase)` に任せる
  （F2 で breaking → working になれば既存ロジックで hide される）
- `hide()` 時のクラッシュ回避策（CLAUDE.md「既知の罠」）に触らない
- F4 のカウントダウンは既存の `remaining` 由来の値から導出できる
  （`breakDuration - remaining >= stopButtonDelay` で有効化）
  （2026-08-09: `stopButtonDelay` は撤廃され `breakActionDelay` に統合。F4参照）

## スコープ外

- 音による告知（ユーザー要望により一切なし）
- スクリーンショット日報ツール（別プロジェクトとして独立に spec を起こす）
- F6c の有効化判断（データ収集後）

- Working 中に約 5 分操作がないと無音で中断セッションとして記録され Idle に戻る
